# 内容矩阵详解（A/B/C/D）

> 4 类内容的**设计逻辑 + 选题判断 + 频次控制**——避免"想拍啥就拍啥"。

## 为什么是 4 类？

**两类太少**（实测+对比），**六类太散**（精力撑不住）。
**4 类是最优**：
- **A 类拉新**（新观众靠"A 类最炸的钩子"进）
- **B 类立深度**（让观众觉得"这人是真懂"）
- **C 类立信任**（让观众觉得"这人是真在用"）
- **D 类拉格局**（让观众觉得"这人看得远"）

**4 类协同**：
- A 是主菜（最多）
- B 是配菜（让主菜更香）
- C 是甜点（让观众成粉丝）
- D 是开胃酒（偶尔活跃一下）

## A 类 · 单项目实测

### 目标
**拉新**——让新观众从"AI 工具推荐"搜索词进来看

### 形态
- 完整测 1 个项目
- 5-10 步实测过程
- 1-2 个真香点 + 1-2 个翻车点
- 最终推荐/不推荐

### 时长
**10-15 min**（A 类不能太短，否则"实测"显得没深度）

### 频次
**每周 1-2 条**（A 类是**产量主力**）

### 选题来源
- 调研池里"已测完"的项目
- GitHub Trending 前 10
- 朋友/同事推荐
- 评论区/私信留言

### 标题公式
- "我试了 XXX：号称 YY，但实测发现 ZZZ"
- "XXX 实战：跑了 3 个项目，结论是..."
- "GitHub 上最火的 XXX，到底有没有用？"

### 翻车点必须存在
**没翻车点的项目不做 A 类**——**因为"全是好话" = 云测评**。

### 范例
D3「我试了 gardener-skill」（已用你日常做的项目举例）

## B 类 · 横向对比

### 目标
**立深度**——让观众觉得"这人不只用过 1 个，能横向看"

### 形态
- 5-10 个同类项目一起测
- 给每个打分（**有量化**）
- 给"该选哪个"建议
- 给出"哪些场景用哪个"

### 时长
**15-20 min**（B 类需要"看完"才能给结论，**不能太短**）

### 频次
**每月 1-2 条**（B 类制作成本高，**少而精**）

### 选题来源
- 调研池里"同类项目"积累到 5+ 个
- 行业里出现新分类（如"AI Agent framework 出了 5 个新项目"）
- 季度复盘发现某个领域值得盘点

### 标题公式
- "我实测了 X 个 [类别]：最该用的是..."
- "[类别] 工具横评：从入门到放弃"
- "GitHub 上 [类别] 工具 Top X，谁是真的好用？"

### 翻车点
- "这 X 个里有 Y 个是垃圾"（**敢说**）
- "排名第一的不一定适合你"（**反排名**）

### 范例
"B 类：5 个 MCP 工具横评"

## C 类 · 整合到工作流

### 目标
**立信任**——让观众觉得"这人是真在用，不是云测评"

### 形态
- 怎么把 XXX 整合进我的 pipeline
- **实操演示**（不是讲理论，**是录屏演示**）
- 踩坑点 + 解决方式
- 最终的 workflow 长啥样

### 时长
**10-15 min**

### 频次
**每月 1-2 条**

### 选题来源
- 调研池里"✅ 可整合"的项目
- 跑 1 个月发现的"新工作流"
- 朋友/同事问我"你怎么用 XXX"

### 标题公式
- "我花了 X 天把 [工具] 整合进 [工作流]，这 3 个坑一定要避"
- "[工具] 实战集成：30 分钟教你塞进我的 pipeline"
- "把 [工具] 用到我的 Hermes 多 agent 编排里"

### 翻车点
- "整合了 2 周才发现不行"（**真实失败**）
- "官方文档没写的坑"（**深度价值**）

### 范例
"C 类：把 gardener-skill 整合进我的 Hermes 工作流"

## D 类 · 行业观察

### 目标
**拉格局**——让观众觉得"这人不只低头干活，还抬头看路"

### 形态
- 行业趋势 / GitHub Trending 盘点
- 某个品类的兴衰分析
- 跨项目的方法论
- "为什么现在大家都在做 XXX" 类解读

### 时长
**8-10 min**（D 类不需要太深，**观点 + 例证**即可）

### 频次
**每月 1 条**（D 类是**最低频**但**调性最高**）

### 选题来源
- GitHub 周报 / 月报
- 行业大事件（如某品类爆发/泡沫破裂）
- 跨项目沉淀的方法论
- 季度复盘输出的洞察

### 标题公式
- "GitHub 本周 Trending 盘点：3 个值得看，5 个是垃圾"
- "AI [类别] 赛道的 3 个反常识"
- "我看了 50 个 [类别] 项目，得出 5 个结论"

### 翻车点
- "这个被吹爆的方向，我不太看好"（**反共识**）
- "这个被低估的方向，反而有机会"（**反共识**）

### 范例
"D 类：GitHub Trending 周报 2026-06"

## 4 类的频次组合

**30 天** = **8-10 条视频**：
- A 类：4-5 条
- B 类：1 条
- C 类：1-2 条
- D 类：1 条
- 自我介绍 / 起号：1 条（仅 D1）

**季度 90 天** = **24-30 条视频**

## 4 类的"不要做"清单

| 类型 | 不要做 |
|---|---|
| A | ❌ 全是好话（云测评）、❌ 太短（< 8 min） |
| B | ❌ 只测 2-3 个（横向没意义）、❌ 没有量化（"我觉得好" = 没说） |
| C | ❌ 只讲理论（不演示）、❌ 30 min 超长（观众没耐心） |
| D | ❌ 拍成新闻播报（"今天 XX 发生了" = 没观点） |

## 4 类的"系列感"设计

**长期看**，4 类应该让观众**有期待感**：
- "下周一肯定有 A 类实测"
- "月底会有 B 类横评"
- "看到 C 类了 = 这人是真在用"
- "月初会有 D 类行业观察"

**系列感 = 节奏 + 预告**：
- 每期视频结尾提"下期会做 X"
- Notion 选题库提前排好 2 周的选题
- B 站/YouTube 简介里写明"每周 X 更新"

## 选题判断的"3 问"

新选题出现时，问自己 3 个问题：

1. **这属于 A/B/C/D 哪一类？**
2. **这类的"翻车点"在哪？没有 = 不做**
3. **观众会记住的 1 句话是什么？**（**写下来**，写不出 = 不做）

**3 个都答得出来 = 进选题库**。**答不出 = 放弃**。
