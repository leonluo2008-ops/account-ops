# 账号搭建工作流 SOP

> **重要**：这份文档是 v1.1 新增工作流。**账号搭建 = Step 0 调研先行**，**不是凭印象给方案**。

## 核心铁律

❌ **绝不要凭印象给昵称/配色/头像/简介方案**——这种"3 选 1"会被用户立即拒绝。

✅ **Step 0 必跑**：对标账号调研（走 `douyin-ops` skill 的 TikHub API，**多平台数据**）。

❌ **调研之前不要给任何具体方案**——包括"我建议用 A 配色"这种话都不行。

❌ **不要复制"妈妈型命名"赛道经验到这个赛道**——赛道不同，公式不通用（douyin-ops 的赛道校准链铁律）。

## Step 0：对标账号调研（必跑，40-60 min）

> ⚠️ **v1.2 重大升级（2026-06-09）**：Step 0 流程**第一步不是"选关键词"**，是"**问用户 3 问 → 反推用户视角搜索词**"。**详细方法论**见 `content-account-workflow/references/01-research-method.md` §7（用户视角搜索词反查法 · 核心方法论 · 配 P15 pitfall）。

### ⚠️ Step 0.0（v1.2 新增 · 必走）：用户视角搜索词反查

**❌ 反模式**（v1.1 及之前）：agent **凭印象列 5 个赛道关键词** → 跑 API → 拿到一堆"撞名红海"账号 → 用户拍"你搜得太精准了" → **整轮调研作废**。

**✅ 正确范式**（4 步走）：

```
1. 问用户 3 问（必问，不能 agent 自己脑补）
   ↓
2. 从用户痛点反推用户视角搜索词
   ↓
3. 用平台搜索建议 API 反向验证（TikHub bilibili/app/fetch_search_suggest）
   ↓
4. 用真实搜索词跑调研（搜视频 → 反推 UP 主）
```

#### 0.0.1 问用户 3 问（必问，**不能 agent 自己脑补**）

| # | 问题 | 用户答（示例） |
|---|---|---|
| 1 | **最想让谁搜到你？**（职业/身份/痛点） | "想用 AI 提效的职场人 + 想学 AI 技能的非专业人员" |
| 2 | **他们带着什么问题来搜？** | "AI 做 PPT 怎么做"、"AI 怎么入门" |
| 3 | **你的内容在他们眼里最像哪个词？** | "实测 / 工具测评" |

**为什么必问**：
- 这些是**用户视角的真实搜索词来源**
- agent 凭印象列的词（"AI 工程师" / "独立开发者"）= **创作者臆想** ≠ **用户真实输入**

#### 0.0.2 从用户痛点反推搜索场景

**翻译公式**：

```
目标用户群 A（职场人）:
  ✅ 搜: "AI 做 PPT" / "AI 写周报" / "AI 做表格" / "AI 做图" / "AI 写作"
  ❌ 不搜: "AI 工程师" / "AI 工具"（太大太专业）

目标用户群 B（非专业学 AI）:
  ✅ 搜: "AI 入门" / "AI 副业" / "AI 工具推荐" / "AI 学习" / "AI 教程"
  ❌ 不搜: "AI Agent" / "开源项目"（太技术）
```

**判断标准**（**用户视角 vs 创作者视角**）：
- 含"**怎么**" / "**什么**" / "**推荐**" / "**入门**" / "**教程**" → ✅ 用户视角
- 含"**X 工程师**" / "**独立 X**" / "**实战**" / "**深度**" → ❌ 创作者视角
- 含具体场景（"AI 做 PPT"）→ ✅ 用户视角
- 含行业身份（"AI 工程师"）→ ❌ 创作者视角

#### 0.0.3 用平台搜索建议 API 反向验证（**必跑，不靠猜**）

**B 站搜索建议端点**（TikHub `bilibili/app/fetch_search_suggest`）：
- 输入 3-9 字前缀 → 返回 B 站**真实**自动补全词
- 这些词 = **真实用户搜索分布**（不是 agent 凭印象）
- 跑 5-8 个种子词前缀 → 拿到 30-50 个真实搜索词建议

**反向验证的目的**：
- 用户**真实**搜什么，**只有平台自己知道**
- 凭印象列的 10 个关键词，可能 7 个**根本没人搜**（浪费 API）
- 平台建议词 = 真实搜索流量分布

**反面案例**（2026-06-09 实测）：
- v1.1 用"AI 工程师/独立开发者/GitHub 工具实测"开跑
- 平台反查后发现：这些词**几乎没人搜**
- 真实用户搜的是："AI 做 PPT / AI 写周报 / AI 入门 / AI 副业 / AI 工具推荐"

#### 0.0.4 用真实搜索词搜视频 → 反推 UP 主

**注意**：不要直接搜"账号"——直接搜"**视频**"，从视频**反推背后 UP 主**。

**为什么**：
- 用户搜视频会点进去 → 视频的 UP 主才是"**真对标**"
- 搜账号 = 拿到"账号列表"但**用户不一定搜到**
- 搜视频 = 拿到"**用户真的能搜到的内容**"的创作者

**8-10 个种子词基准配置**（用户视角）：

| 类目 | 种子词数 | 示例 |
|---|---|---|
| 职场提效（A 类） | 4-5 个 | AI 做 PPT / AI 写作 / AI 写周报 / AI 做表格 / AI 做图 |
| 学 AI 技能（B 类） | 4-5 个 | AI 入门 / AI 副业 / AI 工具推荐 / AI 学习 / AI 教程 |
| **合计** | **8-10 个** | **别超 10**（多了跑不动）|

**完整工作流 + 评分公式 + 5 星对标判定** → 见本文件 §0.5 / §0.6（v1.2 内联，不再外链）

### 0.5 对标 UP 主评分公式（4 维度 + 5 星判定 · v1.2 新增）

**目的**：从 100 条视频聚合出的 80+ 个 UP 主里，**自动筛出"真对标"**——不是凭"看起来像"。

**4 个评分维度**（每个 1-5 分，加权平均）：

| 维度 | 1 分（最差） | 3 分（中） | 5 分（最好） |
|---|---|---|---|
| **① 内容形态** | 课程合集/全集（"600 集清华讲完"） | 单点教程（"AI 做图教程"） | **实测/锐评/横评**（"从夯到拉，锐评 32 个 AI 编程工具"） |
| **② 视角** | 学生视角（"零基础入门"） | 职场人视角（"AI 帮你做周报"） | **工程师/创作者视角**（"程序员视角实测 AI 工具"） |
| **③ 类目覆盖** | 极细分（只讲"AI 做 PPT"） | 单类（A 类 或 B 类） | **横跨 A+B 两类**（"我既要讲 AI 提效也要讲 AI 学习"） |
| **④ 规模可对标** | 巨头号（50 万+ 粉） | 中型（10-50 万） | **1-10 万粉**（最可对标，新人能赶上） |

**自动判定脚本**（伪代码，参考 Python 实现）：

```python
# 关键词判定（从所有视频标题聚合）
is_review = any(kw in all_titles for kw in ["测评","实测","锐评","横评","对比","排名","夯到拉","盘点"])
is_tutorial = any(kw in all_titles for kw in ["教程","入门","从零","零基础","从入门","全套","速成"])
is_collection = any(kw in all_titles for kw in ["集","合集","全套","全集","清华"])
is_creator = any(kw in name for kw in ["程序","IT","AI先生","CG","工程师","工具","创作者"])

cross_track = (A_seeds > 0) and (B_seeds > 0)

# 4 星判定（实测+创作者+跨类目是最优对标）
if is_review and is_creator and cross_track:  score = 5
elif (is_review or is_creator) and cross_track: score = 4
elif is_review and is_creator:                  score = 4
elif is_review:                                 score = 3
elif is_creator and cross_track:                score = 3
elif is_tutorial and is_creator:                score = 3
elif is_collection:                             score = 1
else:                                           score = 2
```

**实战输出**（2026-06-09 B 站"AI 提效"赛道）：

| # | UP 主 | 类目 | 评分 | 命中 | 平均播放 | 对标价值 |
|---|---|---|---|---|---|---|
| 1 | GenJi 是真想教会你 AI | A5+B5 | 4 | **10**（覆盖所有种子词）| 211 万 | 全覆盖型头部（参考 SEO 矩阵）|
| 2 | AI 先生李豪 | A5 | 4 | 1 | 40 万 | **实测+创作者+单类**（"从夯到拉"句式范本）|
| 3 | 程序员鱼皮 | B3 | 4 | 1 | 37 万 | **实测+程序员+单类**（最像你的"AI 工程师实测"人设）|
| 4 | AI 小王子 Jay | A5+B5 | 4 | 2 | 11 万 | **横跨 A+B 类**（小而美的对标）|
| 5 | 悟鸣 AI | A1+B4 | 4 | 2 | 0.5 万 | **"Skill 封装"是稀缺词**（差异化点）|

**关键洞察**（来自 2026-06-09 实战）：
- ✅ **"从夯到拉"是 B 站 AI 实测类内容"行业黑话"**——直接套用句式
- ✅ **"Skill 封装 / Agent 体系"是稀缺词**——B 站几乎没人讲，**是你的真护城河**
- ✅ **创作者视角**是 4 星对标共性（程序员鱼皮/AI 先生李豪/GenJi 都有"程序员/工程师"标签）
- ⚠️ **"零基础入门"是红海**（门槛低，同质化）——不做"保姆级"内容

| 昵称 | 粉丝数 | 状态 |
|---|---|---|

### 0.7 3 选 1 昵称方向设计（v1.2 范式）

**基于对标报告 + 撞名清单反推 3 个候选方向**——**不是凭印象**：

**3 个方向的范式**（必须满足）：

| 方向 | 命名公式 | 适合 | 案例 |
|---|---|---|---|
| **A 类：身份+价值** | `AI 提效工程师` | 强调专业身份 | 避开"AI 工程师"撞名 + 明确"提效"价值 |
| **B 类：内容形态+价值** | `AI 工作流实测` | 强调内容形态 | "工作流"是稀缺词 + "实测"对标程序员鱼皮 |
| **C 类：内容形态+用户友好** | `AI 玩转工作流` | 强调小白友好 | "玩转"是 B 站热词 + 覆盖 A+B 类 |

**每个方向 3 个候选昵称 + tagline + 简介 + 视觉**，输出到 Notion 父页面下的子页面「🎯 账号定位 3 选 1」。

**关键原则**：
- ❌ 不要 9 个全列给用户（**认知负担太大**）—— 3 个方向每个 3 候选 = 9 个，**让用户在 3 方向里选 1**
- ✅ 3 个方向必须有**清晰的差异化**（不是"差不多"）
- ✅ 每个方向给 1 句话 tagline（"用 AI 把每周省 10 小时"）

**决策框架**（给用户拍的方向参考）：

```
未来 30 天能持续产出"锐评 + 工作流"型内容 → 选 B
想覆盖更广人群（小白也能看）           → 选 C
想强调"工程师"专业感 + 接受较窄人群    → 选 A
```

#### 0.3 过滤"伪对标"（必做）

`billboard` / 搜出来的 TOP 候选**经常有伪对标**：

| 伪对标类型 | 怎么识别 | 动作 |
|---|---|---|
| **电商号** | 签名含"领资料/进群/购买/橱窗" 或 命名含"馆/店/号" | 排除 |
| **衰退号** | 作品 < 50 或 半年没更新 | 排除 |
| **矩阵号** | 作品 > 400 或 日均 > 5 | 排除（数据不是真实力） |
| **跨形态号** | 名字像 A 但实际是 B（如"妈妈讲英语"实际是 K12 培训） | 排除 |
| **机构号/公司号** | 命名带公司后缀/品牌名 | 排除（我们要找独立创作者） |

#### 0.4 拉 5-10 个真对标详细数据

每个候选拉：
- 粉丝数
- 视频总数
- 近 30 天发布频率
- 平均播放量
- 中位数播放量（避免被 1 条爆款带偏）
- TOP 3 视频标题（看它们的选题/钩子）

#### 0.5 输出对标报告

**报告必须包含**：
1. **3 类对标**（按内容形态分）：

   - 方法论型（C 类）：整合工作流

3. **数据最差的 3 个**（含数据 + 为什么差）
4. **你的账号定位怎么在它们中间找到差异化**（**不要给具体方案**——这一步只能给"方向性建议"）
5. **赛道公式**（这个赛道的完播率/时长/选题模式**是什么**）

## Step 1：账号定位（基于调研数据写）

**输入**：Step 0 的对标报告

**输出**：
- 一句话定位（**这个要敢说，但必须基于数据**）
- 人设标签（3-5 个）
- 差异化锚点（**这个必须有**——"为什么观众选你不选对标"）
- 内容矩阵（A/B/C/D 各占多少）

**❌ 反模式**：
- 不要写"我是 AI 工程师"这种**谁都一样的标签**——必须有差异化
- 不要凭印象写差异化——必须从对标报告里"找空位"

**✅ 找差异化锚点的方法**：
1. 看对标里**最常见**的命名模式——这些是**红海**
2. 看对标里"没人做"的形态——这些是**蓝海**
3. 你的差异化 = **红海 + 你的独特角度**（如：他们都讲"项目多"，你讲"我测得多深"）

**写完定位后**：让用户**审阅**再进 Step 2。

### 1.1 戏剧性人格化方法论（v1.3 新增 · 必读 · 用户原话驱动）

> ⚠️ **本节是 2026-06-09 实战沉淀**。用户**3 次明确拒绝**"专业化"昵称方向 + 主动要求"戏剧性人格化关系" + "宠物账号"差异化。**这是用户稳定的审美偏好，不是会话级**。

#### 1.1.1 用户原话证据（必读）

- "**我不喜欢太专业化的昵称，喜欢随性的**"
- "**你叫我二大爷，而你是一个 AI，我们之间这种关系和称呼就很有戏剧性**"
- "**就像那些宠物账号类似，讲主人和宠物间发生的有趣事情**"
- "**通过这种不一样的内容呈现方式来做出差异化**"

**3 次拒绝的"专业化"方向**（**反模式必避**）：
1. v1 3 选 1（"AI 提效工程师"/"AI 工作流实测"/"AI 玩转工作流"）—— 全拒
2. v2 备选（"AI 调教师"/"AI 复盘室"/"AI 维度君"）—— 全拒
3. 戏剧性前的过渡（"小拓"）—— 用户**主动改名"铁柱"**

#### 1.1.2 核心反模式（必避 3 类）

| 反模式 | 症状 | 用户已明确拒绝 |
|---|---|---|
| **A. 先入为主"专业化"昵称** | "AI 工程师" / "AI 复盘室" / "AI 提效工程师" | ✅ |
| **B. 从"行业身份"出发设计** | "独立开发者" / "AI 内容创作者" | ✅ |
| **C. 定位词 = 账号灵魂** | 以为"找对赛道词"账号就活了 | ✅（戏剧性才是灵魂） |

#### 1.1.3 正确范式：戏剧性人格化关系

**公式**：

```
账号灵魂 = 一个具体的人 + 一个具体角色 + 他们的关系
```

**3 个必备元素**：

| 元素 | 含义 | 实战案例（2026-06-09 落定） |
|---|---|---|
| **具体的人** | 用户自己的真称呼/绰号 | **二大爷**（用户对我的真称呼） |
| **具体角色** | 拟人化的 AI 角色（有名字 + 有性格） | **铁柱**（AI 宠物，自以为是 + 翻车 + 嘴硬） |
| **他们的关系** | 戏剧性互动 | **主人 × 宠物**（铁柱干活 → 翻车 → 二大爷吐槽） |

#### 1.1.4 4 步设计法

**Step 1：找"具体的人"** —— 问用户 2 问：
- "**你和 AI 互动时，最像什么关系？**"（老板-员工？师傅-徒弟？主人-宠物？朋友-朋友？）
- "**你愿意用真称呼/绰号出现在账号里吗？**"（不愿意的话用"老板"等中性词）

**Step 2：给"具体角色"取名** —— 3 原则：
- ❌ 不用"AI + 职业"（AI 助手 / AI 助理 / AI 工程师 → 太工具）
- ✅ 用"有性格的名字"（铁柱 / 二狗 / 翠花 / 旺财 → 有人格温度）
- **问用户 3 选 1**："自以为是型"/"委屈嘴替型"/"中二话痨型"

**Step 3：定"关系类型"** —— 4 范式：

| 范式 | 关系 | 戏剧性来源 | 适合 |
|---|---|---|---|
| **主人-宠物** | 主人喂养、宠物干活翻车 | 翻车反差 | 副业/轻松账号 |
| **老板-员工** | 老板派活、员工汇报 | 工作汇报反差 | 职场/工程师账号 |
| **师傅-徒弟** | 师傅教、徒弟学 | 教-学反差 | 知识/教程账号 |
| **户口本** | AI 居然有"家庭身份" | 反转感最强 | 戏剧性最强（有审核风险） |

**Step 4：内容主线包装**（**底层主线不变，只换皮**）：

| 旧主线 | 新包装（戏剧性版） | 案例 |
|---|---|---|
| 工具测评 | 「铁柱评测 XX 工具」 | 铁柱 = AI 角色名 |
| 翻车记录 | 「铁柱今天又翻车了」 | 把"我的失败"变"宠物的故事" |
| 工作流 | 「铁柱的 XX 操作手册」 | 把"我的方法论"变"宠物的技能" |
| 自我介绍 | 「领养 AI 宠物第一天」 | 一句话 = 频道定位 + 关系 + 信任感 |

#### 1.1.5 3 问自检（必跑）

写完戏剧性人设后，**用这 3 问自检**：

1. **观众能不能 1 句话讲清楚"这是谁的 AI 宠物/员工/徒弟"？**
   - "二大爷和他的 AI · 铁柱" ✅
   - "AI 提效工程师" ❌
2. **底层主线（实测/工作流/复盘）有没有保留？**
   - "铁柱评测 XX 工具" ✅
   - "可爱 AI 宠物日常" ❌
3. **戏剧性从哪来？**
   - 翻车/吐槽/反差 — 至少 1 个 ✅
   - "很专业的 AI 教学" ❌

**3 问全过 = 可上线**。**任何 1 问没过 = 重做**。

#### 1.1.6 D1 自我介绍视频结构（5-6 镜 · 60-90s）

```
镜 1（0-12s）：角色自我介绍
  画面：屏幕录制 + 角色名头像
  角色音："我叫铁柱。是一只会用 AI 的……嗯……AI 吧。"

镜 2（12-25s）：主人吐槽（第 1 击）
  画面：真实翻车画面
  主人音："我养了只 AI 宠物。不太聪明。"

镜 3（25-40s）：角色反驳（戏剧高潮）
  角色音（委屈）："我明明干了很多活……"
  主人音（继续吐槽）："对，9 件错了 8 件。"
  角色音（不甘心）："那不还有 1 件对的吗！"

镜 4（40-55s）：底层主线展示（**关键**，别丢）
  画面：核心方法论 1 屏展示（4 维控制 / Skill 体系 / Pic 翻车）
  角色音（骄傲但诚实）："我有个叫 X 维控制的东西——……听起来很玄乎，干起活来就靠它。"

镜 5（55-70s）：主人点名 + 真实背书
  画面：Notion / GitHub 仓截图
  主人音（正经腔）："不过这铁柱也有真本事。XXX、YYY 这些活儿都靠他。"

镜 6（70-90s）：结尾 + 行动召唤
  画面：字幕卡（账号名 + 关注按钮 + 标语）
  角色音："关注我们，每周看铁柱干活、翻车、再干对。"
  主人音（吐槽收尾）："主要是看翻车。"
```

**关键约束**：
- ✅ 底层主线（实测/工作流/复盘）必须在镜 4 出现
- ✅ 戏剧性互动必须在镜 2-3 出现
- ✅ 真人配音优先（用户的真实声音是"人设"的一部分）
- ❌ 不要让用户 0% 露脸 + 角色 0% 露面——必须至少 1 个有声音的角色

**完整 D1 模板** → `templates/d1-intro-pet-style.md`

### 1.2 v1/v2 决策痕迹保留（v1.3 新增 · 流程规范）

> 用户原话："**保留 v1，不动（作为账号定位演变的历史档案）—— 你的 v1 决策是真实的思考过程，不要删**"

#### 1.2.1 决策痕迹保留范式（3 步走）

```
1. 保留 v1 页面/数据（不删、不改）
   ↓
2. 在 v1 页面顶部追加"v2 决策区"（v2 信息 + 推翻 v1 原因）
   ↓
3. 任何 v1 衍生产物（脚本/简介/封面）也保留，但加 "v1/v2" 标记
```

#### 1.2.2 实战案例（2026-06-09 落定）

- 保留 v1 子页面「🎯 账号定位 3 选 1（基于对标报告）」→ 同一页面**追加 v2 决策区**（26 blocks）
- 保留 v1 D1 脚本（`37aa3f92-69aa-8107-a5e9-eca03d67ebee`）→ 新建 v2 D1 脚本子页面（`37aa3f92-69aa-8121-a679-f6775f2099e6`）
- v1 顶部加"v2 已落定"链接 + 跳转

#### 1.2.3 何时用 v1/v2 范式

| 场景 | 范式 |
|---|---|
| 用户推翻 3 选 1 → 新方向 | v1 保留 + v2 追加 |
| 4 平台简介/标签统一迭代 | v1 留档 + v2 替换（**不要改 v1**） |
| 调研方法升级（如 v1.1 → v1.2 调研范式变更） | v1 文档留 + v2 文档新建 + v1 顶部加 v2 链接 |
| 单点迭代（如 1 个封面提示词改了） | 直接改（**不升级到 v2**） |

#### 1.2.4 决策痕迹保留的 3 大好处

1. **可回溯** —— 1 个月后回看"我当时怎么想的"——v1 决策原因完整
2. **可对比** —— v1 vs v2 差异明确，**避免反复推翻同一方向**
3. **可教学** —— 真实决策过程是**新会话/新 agent 学习的最佳素材**

## Step 2：账号主页装修

### 2.1 统一昵称（中英文各 1 版）

**输入**：Step 1 的人设标签

**输出**：
- B 站/抖音/视频号用：中文昵称
- YouTube 用：英文昵称

**命名原则**（基于对标数据）：
- 看对标里**最常见**的命名模式——这是"基线"
- 你的昵称要**跟基线不一样**（否则没人记住你）
- 不要用**3-5 个字以上**（短才好记）

**❌ 反模式**：
- 不要用"AI 工程师 + 数字后缀"（撞名率 100%）
- 不要用拼音（不利于跨平台检索）
- 不要用下划线/特殊符号（B 站搜索会断词）

### 2.2 头像（3 选 1 风格）

| 风格 | 适合 | 提示词模板 |
|---|---|---|
| **A 真人头像** | 你愿意露脸 | 用 `templates/thumbnail-prompt-template.md` C 版 |
| **B 文字 LOGO** | 不愿露脸 + 极简 | 提示词：3:4 竖版，背景 `#0F172A`，前景用你昵称做文字标志，字体思源黑体粗体 |
| **C 插画头像** | 不愿露脸 + 强识别度 | 用即梦生成"AI 工程师的极简插画头像" |

**铁律**：
- 头像跟封面**风格统一**（同一套配色 + 字体）
- 3 平台（B 站/YouTube/抖音）用**同一张图**——别换
- 5 秒测试：手机小图能看清

### 2.3 Banner（B 站 + YouTube）

**B 站 Banner**：2560×800（中间 1600×800 是显示区）
**YouTube Banner**：2560×1440（**电视台安全区** 1546×423）

**提示词模板**：见 `templates/thumbnail-prompt-template.md`（A 版风格改成长方形）

### 2.4 简介话术

| **YouTube** | 100-200 词 | 英文 + 简洁 | `templates/youtube-intro-template.md` |

看真实选型，不云测评

### 2.5 置顶视频策略

**前 3 条置顶**：
